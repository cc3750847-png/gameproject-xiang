# UI 规范文档：湘江文旅小游戏移动端

整理日期：2026-04-25  
适用范围：入口、地图、节点、AR 引导、角色、终端、结算页，以及后续三个节点小游戏的统一外壳。  
基准画布：390 x 844，兼容 360 宽小屏、430 宽大屏和桌面预览。

## 1. 设计原则

1. 页面先回答用户三个问题：我在哪、我能做什么、我能不能返回。
2. 一个页面只服务一个主动作，避免把地图、任务、奖励、接口状态都塞进同一块主卡片。
3. 视觉延续现有首页资产：暖纸色、橘棕、柔和江景氛围、宋体标题、清晰正文。
4. 主线 UI 负责“导览与状态”，节点小游戏 UI 负责“玩法外壳”，玩法内部可以有差异但不能破坏统一入口、返回和完成反馈。
5. 文化感来自字体、留白、色彩、图像与文案语气，不靠堆叠装饰。

## 2. 色彩系统

### 2.1 主色

| Token | 色值 | 用途 |
| --- | --- | --- |
| `paper-0` | `#fffaf4` | 页面最高亮底色、弹层正文底 |
| `paper-1` | `#f8efe6` | 默认页面底色 |
| `paper-2` | `#f1e2d1` | 次级分区、弱背景 |
| `river-ink` | `#5d3925` | 主标题、正文强文本 |
| `river-muted` | `rgba(93, 57, 37, 0.72)` | 正文弱文本、说明 |
| `orange-main` | `#b86f3e` | 主按钮、当前状态、关键强调 |
| `orange-deep` | `#8f4b22` | 深色强调、图标描边 |
| `gold-soft` | `#e0a06c` | 完成、奖励、高亮边缘 |
| `blue-river` | `#5f92a8` | 地图、水流、AR 辅助信号 |
| `green-life` | `#6f9962` | 可进入、成功、文化收集 |
| `red-alert` | `#b85a4a` | 错误、权限失败、危险提示 |

### 2.2 使用规则

- 页面底色以 `paper-1` 为主，不使用大面积深蓝黑作为常态页面。
- 主按钮使用 `orange-main -> gold-soft` 的轻渐变或实色，按钮文字使用 `#fffaf4`。
- 状态标签使用低饱和底色，不做刺眼霓虹。
- AR 层可临时进入深色沉浸背景，但顶部状态和关闭按钮必须高对比。
- 奖励和完成反馈使用金色高亮，但不让全页变成单一金色。

## 3. 字体与排版

### 3.1 字体角色

| 角色 | 字体建议 | 用途 |
| --- | --- | --- |
| 文化标题 | Source Han Serif CN / Noto Serif SC / Songti SC | 页面标题、节点名、奖励标题 |
| 正文 | system-ui / Noto Sans SC / Microsoft YaHei | 说明、按钮、列表、状态 |
| 数字与状态 | system-ui | 距离、进度、计数、接口状态 |

### 3.2 字号层级

| 层级 | 移动端字号 | 行高 | 用途 |
| --- | --- | --- | --- |
| H1 | 28-34px | 1.12 | 页面主标题 |
| H2 | 20-24px | 1.25 | 面板标题、节点标题 |
| H3 | 16-18px | 1.35 | 卡片标题 |
| Body | 14-16px | 1.55 | 正文说明 |
| Meta | 11-12px | 1.35 | 标签、状态、辅助信息 |
| Button | 15-16px | 1.2 | 主按钮、次按钮 |

规则：

- 移动端标题最多两行，超过两行必须改短文案。
- 按钮文案最多 7 个汉字，必要时用“进入节点”“返回地图”这类短命令。
- 卡片正文最多 2-3 行，长说明进入说明页或弹层。

## 4. 布局与间距

### 4.1 画布

- 设计基准：390 x 844。
- 安全边距：左右 16px，顶部 16-24px，底部预留底部导航 100-116px。
- 主内容最大宽度：移动端 100%，桌面预览限制在 420-440px。
- 页面根布局：背景层 + 内容层 + 固定底部导航 + 可选覆盖层。

### 4.2 间距

| Token | 值 | 用途 |
| --- | --- | --- |
| `space-4` | 4px | 图标和文字间隙 |
| `space-8` | 8px | 标签、列表细间距 |
| `space-12` | 12px | 卡片内部小间距 |
| `space-16` | 16px | 面板 padding、组件间距 |
| `space-24` | 24px | 页面区块间距 |
| `space-32` | 32px | 大节奏分隔 |

### 4.3 圆角

- 小按钮 / 标签：14-16px。
- 卡片 / 面板：18-22px。
- 底部导航：22px。
- 首页位图按钮保留原图形，不额外套卡片。

## 5. 组件规范

### 5.1 页面壳

页面壳包含背景、顶部信息区、页面主体和底部导航。除首页与 AR 层外，所有页面都使用同一内容宽度和底部安全区。

必备状态：

- `default`：普通页面。
- `loading`：定位、接口、资源准备中。
- `error`：权限、接口、定位异常。
- `completed`：任务或节点已完成。

### 5.2 顶部信息区

包含：

- eyebrow：当前模块，如“区域地图”“节点详情”“玩家终端”。
- title：当前页面主标题。
- description：一句说明当前任务。
- statusTag：当前状态，如“演示定位”“可跳过”“已完成”。

规则：

- statusTag 右上角固定，不抢标题主视觉。
- description 不超过 48 个汉字。
- 地图、节点、任务、终端都复用同一信息结构。

### 5.3 按钮

| 类型 | 用途 | 视觉 |
| --- | --- | --- |
| Primary | 当前页面唯一主动作 | 橘棕实底或轻渐变，白字 |
| Secondary | 返回、跳过、查看说明 | 透明或浅纸底，橘棕文字 |
| Icon | 关闭、返回、调试、分享 | 44 x 44 点击热区，图标居中 |
| Danger | 放弃、重置、权限失败处理 | 红色弱底，红棕文字 |

状态：

- `default`：可点击。
- `pressed`：下压 1px 或降低亮度。
- `disabled`：透明度 45%，不显示强阴影。
- `loading`：文案改为“处理中”，禁止重复点击。

### 5.4 状态标签

标签文本建议固定：

- 启序
- 定位中
- 演示定位
- 真实定位
- 可进入
- 不可进入
- 可跳过
- 收集中
- 已完成
- 已跳过
- 接口异常
- 终章

颜色规则：

- 普通：浅纸底 + 橘棕字。
- 成功：浅绿底 + 深绿字。
- 警告：浅金底 + 橘棕字。
- 错误：浅红底 + 红棕字。

### 5.5 卡片与面板

卡片只用于独立对象：地图节点、任务目标、奖励、成就、明信片。不要用卡片套卡片。

通用结构：

- 顶部：标题 + 状态。
- 中部：1-2 行摘要。
- 底部：主操作或辅助信息。

视觉规则：

- 背景使用半透明暖纸色。
- 边框使用 `rgba(181, 117, 69, 0.16)`。
- 阴影轻，避免厚重 App 商城感。
- 卡片之间间距 10-12px。

### 5.6 底部导航

固定四项：

1. 主页
2. 地图
3. 角色
4. 终端

规则：

- AR 引导层打开时隐藏底部导航。
- 当前页高亮使用浅纸底和橘棕字。
- 每项保留图标 + 文字，图标来自 `public/home`。
- 小屏下底部导航高度不超过 82px。

### 5.7 AR HUD

AR HUD 是唯一允许深色沉浸视觉的界面。

必须包含：

- 顶部左侧：模式标签，如“AR 引导”。
- 顶部或中心：方向提示，如“请向左转动”“目标已锁定”。
- 顶部右侧：关闭按钮。
- 中央：扫描框或粒子汇聚区。
- 底部：一句当前状态说明。
- 调试控件默认收起。

状态：

- `seeking`：方向引导明显。
- `aligning`：提示变弱，强调接近。
- `locked`：金色/绿色完成反馈。
- `lost`：提示信号中断，提供重新对准说明。

### 5.8 奖励反馈

奖励反馈包含：

- 奖励名。
- 奖励来源节点。
- 可视化卡片或图标。
- 下一步按钮。

完成页优先展示“已获得什么”，再展示“下一步去哪”。不要在完成页同时放复杂地图列表。

## 6. 页面状态覆盖

| 页面 | 必须覆盖状态 |
| --- | --- |
| 入口页 | 默认、继续旅程、设置/成就入口 |
| 地图页 | 未定位、定位中、演示定位、真实定位、无可进入节点、可进入节点 |
| 节点详情 | 可开始、不可进入、已跳过、已完成 |
| 节点任务 | 收集中、单项完成、全部完成、退出确认 |
| AR 引导 | seeking、aligning、locked、lost、权限失败 |
| 共鸣页 | 未按住、按住中、完成 |
| 角色页 | 默认头像、自定义头像、身份未选、身份已选 |
| 终端页 | 无成就、有成就、无明信片、有明信片、上传失败 |
| 结算页 | 无奖励、有明信片、可分享、分享失败 |

## 7. 资源复用与缺口

### 7.1 已有资源继续复用

- 首页背景：`public/home/background.png`
- 旅程背景：`public/home/journey-background.png`
- 首页标题：`public/home/extracted/title-wordmark-image2.png`
- 首页按钮：`public/home/extracted/button-*-new.png`
- 底部导航图标：`public/home/icon-spot.png`、`icon-map.png`、`icon-character-new.png`、`icon-achievement.png`

### 7.2 P1 缺口

- 八关节点图标：觉醒、挥毫、问学、天问、百工、镇守、守望、鼓瑟。
- 三身份图标：镇江者、拾遗者、燃火者。
- 状态标签图标：定位、可进入、完成、错误。
- 奖励图标：明信片、文脉碎片、灵韵、称号。
- AR 扫描框角标和粒子母题。

### 7.3 P2 缺口

- 三个 MVP 节点小游戏的玩法区专属视觉。
- 节点完成页强化插画或纹理。
- 解锁下一节点动效素材。

### 7.4 P3 缺口

- 终章分享海报模板。
- 不同身份结局海报背景。
- 可兑换权益入口卡图。

## 8. 前端实现前置约束

- 不新增后端 API。
- 不改变节点小游戏接口，只统一 UI 外壳。
- 优先拆 UI shell 和页面组件，不先重写业务状态。
- 所有新增组件应支持 360px 宽度，不依赖固定高度撑开。
- 所有用户可见文字必须来自页面配置、节点配置或组件 props，避免散落在组件内部。
