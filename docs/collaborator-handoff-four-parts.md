# 四部分协作者交接包

本文档用于把当前项目拆分给 4 位协作者并行推进：

1. UI 协作者
2. 节点游戏 A 协作者
3. 节点游戏 B 协作者
4. 节点游戏 C 协作者

当前项目不是 4 个并列小游戏，而是“一个主线中枢 + 三个节点游戏 + 一个终章收束”的结构。三个节点游戏都必须从主线进入，并在完成后返回主线。

## 统一前提

- 主线中枢负责整体流程推进、状态刷新、节点解锁和终章汇总
- 三个节点游戏只负责各自内部闭环，不单独负责全局主线逻辑
- UI 协作者负责统一视觉语言和统一外壳，不负责具体玩法逻辑
- 三个节点游戏都必须遵守统一接口合同与统一返回规则

## 一、交给 UI 协作者

### 你负责什么

- 主线中枢的统一视觉风格
- 三个节点游戏的统一外壳
- 全局按钮、标签、卡片、弹层、完成反馈组件
- 扫描态、接近态、共鸣态、完成态、终章态等状态样式
- 可复用图标、粒子、背景、按钮态、完成反馈资源

### 你不负责什么

- 每个小游戏内部玩法设计
- 主线跳转逻辑
- 各模块的业务状态判断

### 你最少要交什么

1. 主线中枢页视觉规则
2. 扫描引导层视觉规则
3. 三个节点游戏统一外壳规范
4. 完成页结构规范
5. 终章留痕页视觉方向
6. 关键状态样式清单
7. 共用资源需求清单

### 你交付时怎么描述

- 统一色彩与字体建议
- 主按钮 / 次按钮 / 标签 / 卡片 / 弹层规范
- 扫描框、粒子、锁定态、完成态的视觉示意
- 三个小游戏哪些部分必须统一，哪些部分允许自由发挥

### 你先对齐这些文档

- `xiang-river-obsidian-vault/04-协作与汇报/24-UI接口清单.md`
- `xiang-river-obsidian-vault/04-协作与汇报/26-UI资源需求表.md`

## 二、交给节点游戏 A 协作者

### 当前模块标识

- 建议代称：节点游戏 A
- `gameId`: `river-sound`
- `stageId`: `guiding`
- 当前在主线里的位置：主线引导后的第一个节点闭环

### 你负责什么

- A 游戏进入页 / 过渡页
- A 游戏核心玩法页
- A 游戏完成页
- A 游戏返回主线时的结果回传

### 你最少要做出什么结构

1. 进入页
2. 玩法页
3. 完成页
4. 返回主线动作

### 主线传给你的最小信息

- `nodeId`
- `nodeTitle`
- `chapterProgress`
- `entryText`
- `rewardPreview`

### 你返回主线时至少要带回

- `nodeId`
- `completed`
- `reward`
- `unlockNext`
- `recordForFinale`

### 你要遵守的统一规则

- 从主线进入，不自己另起入口
- 顶部信息区、返回主线按钮、完成反馈结构必须和统一 UI 对齐
- 不能只有玩法页，必须有完成页和返回逻辑

### 你先对齐这些文档

- `xiang-river-obsidian-vault/04-协作与汇报/25-三个节点游戏接入规范.md`
- `docs/game-line-apis.md`

## 统一验收口径

交给每位协作者时，都要求对方至少回答清楚这 4 件事：

1. 你负责的页面结构是什么
2. 你依赖主线或 UI 提供什么
3. 你完成后要回传什么状态
4. 你交付后主线怎么把它接回去

## 一句话交接口径

UI 协作者负责统一语言，三个节点游戏协作者各自负责“进入页 -> 玩法页 -> 完成页 -> 返回主线”的闭环；所有人都必须围绕主线中枢来工作，而不是各做各的独立小项目。
