# 听声辨位、地图节点与 AR 辅助约束

更新时间：2026-04-27

这份文档记录当前网页游戏必须遵守的一条核心产品逻辑：**AR 不是独立玩法，而是“听声辨位”的辅助表现层；听声辨位的目的，是把游客分流到地图上的不同任务节点。**

## 核心定位

### 听声辨位

听声辨位是主体验机制。玩家根据声音方向、远近、强弱或节奏提示，判断自己应该往哪个方向移动。

它的产品目的不是单纯做感官演示，而是：

- 引导游客从当前聚集区分流到不同区域；
- 让游客理解“我现在在哪、我要去哪个节点、为什么要移动”；
- 把线下空间中的不同点位组织成可探索的任务网络。

### AR 辅助

AR 是听声辨位的辅助，不应独立成为主玩法。

AR 的作用是：

- 在听声辨位过程中提供可视化方向提示；
- 当声音判断不够明确时，用粒子、指向、锁定框等视觉提示帮助玩家校准；
- 在靠近任务节点时强化“已经接近目标范围”的反馈。

因此，界面文案和 IA 中应优先表达“听声辨位 / 循声前往”，其次才表达“AR 辅助 / AR 引导”。

## 地图的必要性

由于听声辨位承担游客分流，玩家需要一个地图来理解当前空间关系。

地图需要回答三个问题：

1. 我当前在什么位置？
2. 附近有哪些任务节点？
3. 每个节点的有效范围在哪里？

地图不只是装饰性的导航背景，而是任务系统的基础层。

## 开发者锚定节点

任务节点应由开发者在地图上配置。

每个节点至少需要包含：

- 节点 ID；
- 节点名称；
- 地图坐标或地理坐标；
- 有效半径 / 范围；
- 节点说明；
- 任务内容；
- 奖励内容；
- 是否可见 / 是否启用；
- 是否允许跳过。

用户进入节点范围后，才可以完成相应任务并获得奖励。

## 用户侧节点规则

用户在地图上的状态应分为：

- 未靠近：节点可见，但不可完成任务；
- 接近中：听声辨位和 AR 辅助提示增强；
- 已进入范围：任务可开始或可完成；
- 已完成：奖励已获得，节点状态变为完成；
- 已跳过：不领取奖励，但可继续主线或前往其他节点。

## 对主界面的影响

点击“开始游戏”后的主界面应强调：

- 当前定位状态；
- 当前最近或推荐节点；
- 节点范围提示；
- 听声辨位入口；
- AR 辅助入口，但它应依附于听声辨位；
- 地图入口；
- 当前任务和奖励状态。

推荐主按钮文案：

- “开始听声辨位”
- “循声前往节点”
- “继续循声”

不推荐把主按钮写成：

- “开启 AR”
- “进入 AR”

除非当前页面明确说明 AR 只是听声辨位的辅助。

## 对 IA 的修正

后续 IA 应采用下面的关系：

```text
地图
  -> 显示当前位置
  -> 显示开发者锚定的任务节点
  -> 显示节点有效范围
  -> 选择或推荐目标节点
  -> 听声辨位
      -> AR 辅助校准
      -> 进入节点范围
      -> 完成节点任务
      -> 获得奖励
```

关键结论：

- 地图是空间理解层。
- 听声辨位是分流与移动引导层。
- AR 是听声辨位的辅助表现层。
- 节点范围是任务解锁条件。
- 奖励绑定节点任务完成，而不是单纯绑定 AR 操作。
