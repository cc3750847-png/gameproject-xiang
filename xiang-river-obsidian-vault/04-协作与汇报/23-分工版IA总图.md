## 文档用途

这份文档面向组内原型推进与任务分工。  
重点不是视觉呈现，而是把产品结构、页面边界、节点游戏接入方式和 UI 负责人协作边界定义清楚。

## 核心结构

这套产品不是四个并列小游戏，而是：

- 一个主线中枢
- 三个节点游戏
- 一个终章收束模块

玩家始终在主线里移动，只在到达特定节点时进入对应游戏。  
每个节点游戏完成后，再返回主线继续推进，最后进入终章留痕。

## IA 主链路

整体信息架构可以先理解成下面这条主链：

1. 入口启动
2. 主线中枢首页
3. 主线扫描 / 引导状态
4. 到达节点 A
5. 进入游戏 A
6. 返回主线中枢
7. 到达节点 B
8. 进入游戏 B
9. 返回主线中枢
10. 到达节点 C
11. 进入游戏 C
12. 返回主线中枢
13. 终章留痕 / 奖励 / 海报

## 结构分层

为了后续协作更清楚，建议把 IA 分成 4 层。

### 1. 全局层

内容包括：

- 入口页
- 权限请求
- 主线总进度
- 全局状态栏
- 终章留痕
- 奖励与纪念内容

这一层是所有人共享的产品骨架。

### 2. 主线中枢层

内容包括：

- 当前阶段提示
- 下一节点引导
- 摄像头扫描层
- 粒子引导层
- 到点确认
- 进入节点游戏的跳转页
- 从节点游戏返回后的状态刷新

这一层是整个项目的交通系统。

### 3. 节点游戏层

内容包括：

- 游戏 A 独立流程
- 游戏 B 独立流程
- 游戏 C 独立流程

每个节点游戏都应被视为独立模块，但必须遵守统一接入规则：

- 从主线进入
- 有自己的核心玩法页
- 完成后返回主线
- 返回时给主线一个完成状态

### 4. 统一 UI 层

内容包括：

- 色彩系统
- 字体系统
- 按钮体系
- 弹层体系
- 状态标签
- 扫描框样式
- 粒子母题
- 节点标题样式
- 终章海报样式
- 三个节点游戏的统一壳层规范

这一层由 UI 负责人横向覆盖，不归单个玩法独占。

## 分工视角下的 IA 拆分

### 1. 主线负责人

负责这些页面和状态：

- 入口页
- 主线中枢页
- 扫描引导页
- 节点到达确认页
- 节点跳转页
- 节点完成返回后的主线状态
- 终章留痕页

主线负责人本质上负责所有游戏之间的连接关系。

### 2. 游戏 A 负责人

负责：

- 游戏 A 进入页或过渡页
- 游戏 A 玩法页
- 游戏 A 完成页
- 返回主线的接口状态

### 3. 游戏 B 负责人

负责：

- 游戏 B 进入页或过渡页
- 游戏 B 玩法页
- 游戏 B 完成页
- 返回主线的接口状态

### 4. 游戏 C 负责人

负责：

- 游戏 C 进入页或过渡页
- 游戏 C 玩法页
- 游戏 C 完成页
- 返回主线的接口状态

### 5. UI 负责人

负责整个项目统一样式，不单独拥有某条页面流程，但要覆盖：

- 主线中枢视觉规范
- 三个节点游戏的统一框架
- 全局组件与视觉资源
- 状态与反馈样式
- 共用图标、粒子、按钮、标签、卡片、提示样式

## 关键接口规则

为了避免后续各做各的，三个节点游戏必须统一遵守以下接口规则。

### 1. 进入接口

主线到达节点后，进入该游戏时至少要传：

- 当前节点名
- 当前章节进度
- 玩家已获得的主线状态
- 该节点对应的引导文案或标题

### 2. 退出接口

节点游戏完成后，返回主线时至少要带回：

- 是否完成
- 奖励内容
- 是否解锁下一段主线
- 是否需要更新终章留痕材料

### 3. UI 接口

三个节点游戏都应使用统一的：

- 顶部信息样式
- 返回主线方式
- 完成反馈方式
- 奖励展示方式

这样结构和视觉都能保持一致。

## 推荐协作顺序

如果现在就要推进原型和分工，建议按下面这个顺序协作：

1. 主线负责人先把主线中枢 IA 跑通
2. 三个节点游戏负责人各自先做自己的“进入页 -> 玩法页 -> 完成页”
3. UI 负责人同步出一版统一 UI 规则
4. 最后再把三个节点游戏挂回主线里联调

## 一句话总结

这套 IA 的本质是：

主线负责连接和推进，三个节点游戏负责各自玩法，UI 负责人负责统一视觉语言，终章负责回收整段体验。
