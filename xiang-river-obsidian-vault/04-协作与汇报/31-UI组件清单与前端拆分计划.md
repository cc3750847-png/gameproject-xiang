# UI 组件清单与前端拆分计划

来源：项目文件 `docs/ui-component-checklist.md`  
目标：把当前集中在 `src/App.tsx` 的页面结构拆成可复用 UI 组件，同时不改业务逻辑、不新增后端 API。

## 当前页面状态映射

| 当前状态 | UI 页面 | 说明 |
| --- | --- | --- |
| `entry` | 入口页 | 首页菜单，开始/继续/设置/成就入口 |
| `map` | 地图页 | 定位、节点 marker、节点列表、继续主线 |
| `node-detail` | 节点详情页 | 节点任务说明、开始或跳过 |
| `photo-task` | 节点任务页 | 三目标拍摄任务和明信片奖励 |
| `journey` | 主线页 | guiding、approaching、resonance、completion、handoff、finale |
| `character` | 角色页 | 头像、称号、等级、完成统计 |
| `terminal` | 终端页 | 玩家信息、成就、收藏、设置 |
| `isScannerOpen` | AR 引导层 | 全屏覆盖层，隐藏底部导航 |

## 组件拆分顺序

第一阶段只拆 UI shell 和表现组件，不重写状态机。

1. `AppShell`：背景、页面宽度、底部安全区、是否首页/旅程页。
2. `PageHeader`：eyebrow、title、description、statusTag。
3. `BottomNav`：主页、地图、角色、终端四项导航。
4. `ActionButtons`：主按钮、次按钮、loading/disabled 状态。
5. `StatusTag`：统一状态标签颜色和尺寸。
6. `MapPage`：地图、节点列表、定位按钮。
7. `NodeDetailPage`：节点说明、任务预览、开始/跳过。
8. `NodeTaskPage`：目标清单、拍摄按钮、奖励卡。
9. `ArGuidanceOverlay`：AR HUD、粒子层、调试面板。
10. `PlayerTerminalPage` 与 `CharacterPage`：玩家档案、统计、收藏区。
11. `SettlementPage`：终章明信片和分享反馈。

## 关键组件接口

### AppShell

Props：`mode`、`children`、`showBottomNav`、`bottomNavProps`。

职责：决定背景资源、控制内容最大宽度、给底部导航预留安全区。

### PageHeader

Props：`eyebrow`、`title`、`description`、`statusTag`、`statusTone`。

职责：统一每页“我在哪”的信息结构，控制标题行数和状态标签位置。

### BottomNav

Props：`activeView`、`onHome`、`onMap`、`onCharacter`、`onTerminal`。

职责：统一主页、地图、角色、终端四项导航。

### MapPage

Props：`locationStatus`、`nodes`、`onRefreshLocation`、`onOpenNode`、`onContinueMainline`。

节点数据：`id`、`title`、`summary`、`distanceMeters`、`isReachable`、`status`。

### NodeDetailPage

Props：`node`、`taskStatus`、`onStartTask`、`onSkipTask`、`onBackToMap`。

### NodeTaskPage

Props：`node`、`task`、`reward`、`onCaptureTarget`、`onBackToMap`。

### ArGuidanceOverlay

Props：`cameraStatus`、`guidanceState`、`particleField`、`guidanceCopy`、`guidanceHint`、`audioLevel`、`isDebugOpen`、`onClose`、`onToggleDebug`、`onSetDemoDeviation`、`onSimulateLostSignal`。

### RewardCard

Props：`title`、`caption`、`tone`、`meta`、`actionLabel`、`onAction`。

### PlayerSummary

Props：`nickname`、`title`、`avatarDataUrl`、`level`、`completedCount`、`postcardCount`、`achievementCount`。

## 静态配置整理

建议从 `App.tsx` 移出：

- `MAP_NODES`：移至 `src/features/map-nodes/mapNodeConfig.ts`。
- `STAGE_GAME_IDS`：移至 `src/features/journey/stageGameConfig.ts`。
- 页面展示文案：保留在 `src/features/journey/screens.ts` 或拆为 `viewCopy.ts`。
- UI 状态文案：移至 `src/features/ui/statusCopy.ts`。

第一阶段不移动：

- localStorage 玩家状态逻辑。
- AR 音频和摄像头副作用。
- API 联调调用逻辑。

## 前端拆分验收标准

- `App.tsx` 不再直接承载大段 JSX 页面块，只负责状态组合和路由式分发。
- 每个页面组件都可以通过 props 独立理解。
- 底部导航、顶部信息区、状态标签、奖励卡不重复实现。
- 现有测试仍覆盖入口、地图、节点任务、AR、终端、结算主流程。
- 不新增后端 API，不改变现有 `/api/games/:gameId/*` 合同。

## 实施批次

1. UI Shell：拆出 `AppShell`、`PageHeader`、`StatusTag`、`BottomNav`、`ActionButtons`。
2. 页面组件：拆出 `MapPage`、`NodeDetailPage`、`NodeTaskPage`、`SettlementPage`。
3. 沉浸层与玩家页：拆出 `ArGuidanceOverlay`、`CharacterPage`、`PlayerTerminalPage`。
4. 视觉细化：根据 UI 规范调整 tokens、按钮、卡片、状态标签、奖励卡。
