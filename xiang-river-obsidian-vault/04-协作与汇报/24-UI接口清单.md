## 文档用途

这份文档面向整个项目的统一 UI 负责人。  
目标不是定义具体美术风格，而是明确：

- UI 负责人需要覆盖哪些页面
- 需要统一哪些组件
- 需要定义哪些状态样式
- 需要准备哪些共用资源

这份清单的作用，是让 UI 负责人可以在不接管所有页面结构的情况下，稳定输出整个项目的一致视觉语言。

## UI 负责人职责边界

UI 负责人负责的是整个项目的统一视觉规则，而不是某一个节点游戏的具体玩法逻辑。

它应覆盖：

- 主线中枢的视觉风格
- 三个节点游戏的统一外壳
- 全局交互组件样式
- 状态反馈样式
- 共用视觉资源
- 终章留痕与奖励出口的统一呈现

它不单独负责：

- 每个节点游戏的玩法结构设计
- 主线逻辑跳转规则
- 各模块的业务状态判断

## 一、页面覆盖范围

UI 负责人需要明确覆盖以下页面或页面层。

### 1. 主线中枢相关

- 入口启动页
- 主线中枢页
- 扫描引导层
- 节点到达确认页
- 节点跳转页
- 节点完成反馈页
- 返回主线后的刷新状态

### 2. 三个节点游戏相关

每个节点游戏都需要有统一外壳规范，包括：

- 进入页 / 过渡页
- 玩法页的顶部信息区
- 完成页
- 返回主线入口

注意：

三个游戏内部玩法可以不同，但外层框架应保持统一识别。

### 3. 终章相关

- 终章留痕页
- 海报生成入口
- 奖励 / 福利入口
- 旅程摘要区

## 二、统一组件清单

这些组件应由 UI 负责人先定义，再供主线和三个节点游戏复用。

### 1. 顶部信息组件

用于展示：

- 当前章节
- 当前节点
- 进度状态
- 状态标签

需要定义：

- 桌面与移动端布局规则
- 文本层级
- 标签样式
- 是否允许折叠

### 2. 主按钮与次按钮组件

适用于：

- 开始旅程
- 继续主线
- 进入节点游戏
- 返回主线
- 生成海报

需要定义：

- 主按钮样式
- 次按钮样式
- 禁用态
- 加载态
- 点击反馈态

### 3. 状态标签组件

用于展示：

- 启序
- 导流中
- 接近中
- 仪式中
- 已完成
- 已解锁
- 终章

需要定义：

- 标签颜色规则
- 文字层级
- 背景处理
- 小尺寸与标准尺寸版本

### 4. 卡片 / 面板组件

适用于：

- 主线中枢信息卡
- 节点确认卡
- 小游戏入口卡
- 终章摘要卡

需要定义：

- 圆角
- 阴影
- 描边
- 背景透明度
- 内容留白规则

### 5. 弹层 / 覆盖层组件

适用于：

- 扫描层
- 权限说明层
- 节点说明层
- 奖励弹层

需要定义：

- 遮罩深浅
- 顶部关闭方式
- 弹层进入动画
- 文本和按钮布局规则

### 6. 完成反馈组件

适用于：

- 节点完成
- 游戏完成
- 解锁下一段主线
- 终章收束

需要定义：

- 成功反馈结构
- 奖励展示方式
- 文案层级
- 下一步按钮位置

## 三、状态样式清单

统一 UI 最容易失控的地方，不在普通页面，而在各种状态变化。  
因此 UI 负责人必须把状态样式单独定义清楚。

### 1. 默认态

页面正常展示时的基础样式。

### 2. 引导态

主线在引导玩家前进时，需要有更强的方向提示感。

### 3. 接近态

接近节点时，需要有“已经快到”的强化视觉状态。

### 4. 扫描态

摄像头扫描打开后，需要有与普通页面明显不同的沉浸感。

### 5. 共鸣态

长按共鸣时，界面需要有持续增强的反馈节奏。

### 6. 完成态

完成节点或完成小游戏后，需要有清晰的“已达成”视觉语言。

### 7. 解锁态

当新节点或新游戏被开启时，需要有统一的解锁反馈方式。

### 8. 终章态

终章不能只沿用普通页面状态，应有更强的收束与纪念感。

## 四、共用资源清单

这部分是 UI 负责人后续最需要准备给大家复用的资源。

### 1. 图标资源

- 主线进度图标
- 节点类型图标
- 奖励图标
- 返回主线图标
- 摄像头 / 扫描相关图标

### 2. 粒子与引导资源

- 主线粒子母题
- 汇聚粒子版本
- 扫描框边角资源
- 节点锁定视觉元素

### 3. 背景与纹理资源

- 主线中枢背景基底
- 扫描层背景处理方式
- 节点进入页统一背景逻辑
- 终章留痕背景

### 4. 按钮与反馈资源

- 主按钮态
- 次按钮态
- 禁用态
- 完成反馈高亮态

### 5. 终章资源

- 海报模板
- 旅程摘要卡
- 奖励展示壳层

## 五、对三个节点游戏的统一要求

UI 负责人虽然不负责每个游戏的玩法逻辑，但必须给三个节点游戏一套统一接入规范。

### 统一项

- 顶部标题结构
- 章节 / 节点信息的展示方式
- 返回主线按钮样式
- 完成页结构
- 奖励展示结构

### 可变化项

- 每个游戏的核心玩法区
- 每个游戏内部的专属动效
- 每个游戏局部强化色

建议原则：

- 外壳统一
- 核心玩法区允许差异
- 完成反馈重新统一

## 六、交付给 UI 负责人的最小清单

如果现在就要让 UI 负责人开工，最少需要先交给他以下内容：

1. 主线中枢页结构
2. 扫描层结构
3. 节点游戏统一外壳结构
4. 完成页结构
5. 终章留痕结构
6. 关键状态列表
7. 共用资源需求表

这 7 项一旦明确，UI 负责人就可以开始做统一视觉规则，而不需要等所有玩法都做完。

## 七、一句话总结

UI 负责人的任务不是把所有页面“画漂亮”，而是建立一套能横跨主线中枢、三个节点游戏和终章留痕的统一界面语言。
