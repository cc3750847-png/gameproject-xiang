## 目标

- 优先手机 Web 端，便于快速部署、演示与分享
- 先搭稳定的原型环境，再逐步接入 AR、定位与剧情状态
- 让前端结构足够轻，便于后续迭代页面和交互

## 技术栈

- 构建工具：Vite
- UI 框架：React + TypeScript
- 样式方案：Sass + CSS Variables
- 状态管理：Zustand
- 测试：Vitest + Testing Library
- 代码规范：ESLint + Prettier
- 部署方向：静态站点优先，可落地到 Vercel / Netlify / 学校服务器

## 选择原因

### 为什么不先上小程序跨端框架

当前阶段的核心目标是：

1. 快速做出手机可访问、可演示、可迭代的原型
2. 先验证主线交互和页面结构是否成立
3. 降低前期脚手架复杂度和调试成本

因此先采用移动 Web 方案更合适，后续如果确定需要转向更强的小程序能力，再考虑跨端迁移。

### 为什么选 Vite

- 初始化快
- 本地开发体验轻
- 构建静态部署方便
- 适合前期原型与中小型交互项目

### 为什么选 React + TypeScript

- 组件化适合页面状态拆分
- TypeScript 方便后续管理节点、流程和剧情状态
- 生态成熟，便于后续加测试和状态管理

### 为什么选 Zustand

- 比较轻
- 适合管理主线状态、节点解锁和旅程进度
- 前期不会因为状态方案过重拖慢搭建

## 前期目录建议

- `src/`：前端源码
- `src/features/`：按功能拆分的模块
- `src/styles/`：全局样式变量与基础样式
- `src/test/`：测试初始化
- `xiang-river-obsidian-vault/`：方案文档与设计沉淀

## 当前阶段交付目标

第一阶段环境搭建完成后，至少应具备：

1. 可运行的移动端首页壳子
2. 基础样式系统
3. 基础测试能力
4. 可执行的构建命令
5. 可继续承接“进入页 -> 主线引导 -> 共鸣 -> 留痕”的页面扩展能力

## 当前脚本

- `npm run dev`：启动本地开发环境
- `npm run build`：执行 TypeScript 校验并打包
- `npm run test`：运行 Vitest 测试
- `npm run lint`：运行 ESLint 校验
- `npm run format`：执行 Prettier 格式化
