## 使用说明

这份文档用于把前面的低保真原型结构进一步落成“可直接照着画”的页面说明。  
重点不是视觉风格，而是每一页的区块布局、信息主次、按钮位置和状态变化。

建议先按移动端竖屏原型理解。

## 页面 1：进入页

### 页面目标

- 玩家扫码后快速理解“这是什么”
- 愿意点击进入
- 不被大量说明挡住

### 建议布局

```text
┌────────────────────┐
│      顶部留白      │
│                    │
│      主标题        │
│     副标题短句     │
│                    │
│   主视觉占位区     │
│  （音乐/粒子意象） │
│                    │
│   [ 开始寻乐 ]     │
│                    │
│ 权限提示小字       │
└────────────────────┘
```

### 区块说明

1. 顶部留白区
   用来给页面气质呼吸，不要一进来就塞满说明。

2. 主标题区
   只放项目主名称，不要叠过多品牌信息。

3. 副标题区
   一句建立气质的短文案，控制在两行以内。

4. 主视觉占位区
   低保真阶段可画成“旋律线 + 粒子汇聚”的示意图。

5. 主按钮
   页面上最显眼的操作，只保留一个。

6. 权限提示
   放在底部小字区域，不要抢视觉重心。

### 交互要点

- 点击主按钮后进入主线引导页
- 首次进入时可弹出系统权限请求

## 页面 2：主线引导页

### 页面目标

- 让玩家一眼知道自己当前在哪
- 明确下一步该做什么
- 提供开启 AR 的入口

### 建议布局

```text
┌────────────────────┐
│ 当前章节     进度   │
│--------------------│
│                    │
│   当前状态文案     │
│  “循乐而行”        │
│                    │
│   中央主视觉区     │
│（路线/粒子/音乐态）│
│                    │
│ [ 开启AR引导 ]     │
│ [ 继续寻乐 ]       │
│                    │
│ 底部辅助信息条     │
└────────────────────┘
```

### 区块说明

1. 顶部状态栏
   左侧放当前章节，右侧放简要进度，例如“1/4”或“已唤醒 1 段灵韵”。

2. 当前状态文案
   始终只保留一条最短提示，不要同时出现多条说明。

3. 中央主视觉区
   低保真可画成抽象粒子流向图，表示系统正在引导玩家前进。

4. AR 按钮
   次主按钮，用于开启视觉辅助。

5. 继续按钮
   主按钮，强调当前主要动作。

6. 底部辅助信息条
   可放“当前位置已更新”“下一处回响已开启”等轻提示。

### 页面状态

#### 常态

- 显示短提示
- 主按钮可用

#### 引导中

- 中央主视觉区增强
- 可显示“正在接近下一处节点”

#### 迷路纠偏态

- 顶部或底部出现额外角色化提示
- 不要弹巨大警告窗

---

## 页面 3：接近节点页

### 页面目标

- 告诉玩家“你已经找对了”
- 从行进态切入到达态
- 为共鸣动作做心理准备

### 建议布局

```text
┌────────────────────┐
│   接近提示小标题   │
│                    │
│    节点名称区      │
│                    │
│   汇聚反馈示意区   │
│ （粒子向中心靠拢） │
│                    │
│  共鸣准备短文案    │
│                    │
│ [ 准备共鸣 ]       │
└────────────────────┘
```

### 区块说明

1. 接近提示
   一句话点明“你已经接近目标”。

2. 节点名称
   不宜太长，更像意象标题而不是说明标题。

3. 汇聚反馈示意区
   视觉重点区域，要让人感觉从“找方向”切到“被确认”。

4. 共鸣准备文案
   告诉玩家接下来要停下来做一个动作。

5. 主按钮
   直接进入共鸣页。

---

## 页面 4：共鸣页

### 页面目标

- 承载长按蓄力动作
- 清晰传达进度变化
- 给玩家明显的完成感

### 建议布局

```text
┌────────────────────┐
│   共鸣标题         │
│   仪式短文案       │
│                    │
│                    │
│   [ 长按区域 ]     │
│  （核心交互圆区）  │
│                    │
│   进度/反馈条      │
│                    │
│   状态反馈文字     │
└────────────────────┘
```

### 区块说明

1. 标题区
   只说明当前动作，例如“与此地共鸣”。

2. 仪式短文案
   给情绪，不给复杂解释。

3. 长按区域
   页面绝对主角，尺寸要足够大。

4. 进度反馈条或环
   可以用圆环，也可以用能量条，但必须很直观。

5. 状态反馈文字
   用于显示“灵韵汇聚中”“回响正在苏醒”“共鸣已成”。

### 状态变化

#### 未开始

- 长按区安静
- 文案提示“长按片刻”

#### 蓄力中

- 进度增长
- 视觉与音乐反馈增强

#### 即将完成

- 颜色或粒子变化更明显
- 强化“快完成了”

#### 完成

- 短暂爆发态
- 自动进入节点完成页

---

## 页面 5：节点完成页

### 页面目标

- 回收玩家刚完成的动作
- 发放明确反馈
- 给出下一步方向

### 建议布局

```text
┌────────────────────┐
│   完成状态标题     │
│                    │
│   资源获得区       │
│                    │
│   剧情短句区       │
│                    │
│   下一步提示区     │
│                    │
│ [ 继续主线 ]       │
│ [ 进入小游戏 ]     │
└────────────────────┘
```

### 区块说明

1. 完成状态标题
   比如“此地回应了你”，先让玩家明确知道成功了。

2. 资源获得区
   用最简方式展示资源、碎片或进度提升。

3. 剧情短句区
   一小段文化或叙事回报，不宜过长。

4. 下一步提示区
   告诉玩家下一步是继续主线，还是进入具体小游戏。

5. 双按钮区
   只有在需要时才出现第二按钮。

### 布局原则

- 从上到下形成“成功 -> 获得 -> 理解 -> 行动”的阅读路径

## 页面 6：小游戏衔接页

### 页面目标

- 把主线平滑切入小游戏
- 保证小游戏属于当前旅程的一部分

### 建议布局

```text
┌────────────────────┐
│ 当前小游戏名称     │
│                    │
│ 过渡文案区         │
│                    │
│ 小游戏意象占位区   │
│                    │
│ [ 进入小游戏 ]     │
│ [ 稍后再来 ]       │
└────────────────────┘
```

### 区块说明

1. 小游戏名
   要清楚，不需要藏。

2. 过渡文案
   起桥梁作用，让玩家理解为什么此刻会进入这个玩法。

3. 意象占位区
   低保真可用简单图标或符号表示“投石”“鼓点”“留痕”等。

4. 双按钮
   主按钮进入，次按钮保留弹性。

### 注意点

- 如果这是重要剧情节点，文案可略重
- 如果是普通节点，过渡要短，避免拖慢节奏

---

## 页面 7：终章留痕页

### 页面目标

- 回收整段旅程
- 生成纪念感
- 承接分享和权益兑换

### 建议布局

```text
┌────────────────────┐
│   终章标题         │
│   终章短文案       │
│                    │
│   路线/收集摘要    │
│                    │
│   纪念内容区       │
│                    │
│ [ 生成纪念海报 ]   │
│ [ 查看专属礼遇 ]   │
└────────────────────┘
```

### 区块说明

1. 终章标题
   应该有“命名感”，让玩家觉得自己完成了一段经历。

2. 终章短文案
   负责最后一次角色回应。

3. 摘要区
   展示完成的章节、路线、灵韵或称号。

4. 纪念区
   作为分享主出口，视觉重心可以偏强。

5. 权益区
   作为运营出口，但层级不能压过纪念内容。

---

## 跨页面一致性规则

### 1. 主按钮永远只有一个最强

不能让玩家在主线中每页都面对多个同级选择。

### 2. 文案层级固定

- 标题：说明当前阶段
- 短文案：给气质与引导
- 小字：给说明与补充

### 3. 反馈区位置尽量稳定

例如进度、资源和状态反馈不要每页乱跳，否则玩家会重新学习。

### 4. 角色语气保持一致

不要某一页很诗意，下一页突然变成纯系统口吻。

---

## 最小可画原型顺序

如果现在就开始画，建议优先画这 7 页：

1. 进入页
2. 主线引导页
3. 接近节点页
4. 共鸣页
5. 节点完成页
6. 小游戏衔接页
7. 终章留痕页

这 7 页一旦画出来，已经足够用于：

- 课堂汇报
- 项目讨论
- 原型演示
- 后续细化 UI
